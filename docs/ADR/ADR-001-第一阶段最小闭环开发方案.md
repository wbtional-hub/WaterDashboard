# ADR-001：第一阶段最小闭环开发方案

## 状态

- 状态：已接受
- 日期：2026-06-04
- 依据：V17 主设计文档、`AI_MEMORY.md`、`AI_DEVELOPMENT_RULES.md`
- 说明：本 ADR 固化第一阶段开发范围。基础工程框架为推荐方案，进入编码前仍需最终确认。

## 1. 第一阶段开发目标

建立“统一智慧水务大屏系统”的第一个可运行、可验证、可回归闭环：

```text
独立启动
  -> 配置只读数据源
  -> 创建组件模板
  -> 创建大屏草稿
  -> 拖入组件实例
  -> 配置 SELECT SQL
  -> SQL 预览与字段映射
  -> 保存草稿
  -> 发布前体检
  -> 发布不可变版本
  -> 浏览页加载已发布大屏
  -> 单卡片独立查询与错误隔离
```

核心结果：

- 新增大屏、调整卡片和更换数据源不需要修改代码。
- 草稿修改不影响已发布浏览页。
- 任意单卡片失败不影响整张大屏。
- 所有接口、查询和异常具备 `traceId`。
- 为权限、License 和 Dashboard Context Manifest 留出稳定扩展点。

## 2. 第一阶段不做什么

- 不一次性开发完整智慧水务业务场景。
- 不开发 OpenLayers GIS 卡片、Babylon.js 三维卡片、G6 拓扑卡片。
- 不调用 AI 模型，不实现 AI Gateway，仅预留上下文清单结构。
- 不实现完整 RBAC、ABAC、字段级权限管理页面。
- 不实现完整 License 激活、离线授权、组件签名和资产水印流程。
- 不支持写入型 SQL、存储过程和多语句执行。
- 不写死某一家水务系统的表结构或前端演示数据。
- 不实现复杂联动、动画、主题市场、导入导出和多人协同编辑。

## 3. 后端模块拆分

| 模块 | 职责 |
| --- | --- |
| `common` | 统一响应结构、错误码、`traceId`、异常处理、脱敏工具 |
| `datasource` | 数据源配置、密钥加密存储、连接测试、只读查询 |
| `sql-security` | SQL 解析、仅允许 `SELECT`、多语句拦截、限行、超时 |
| `component-template` | 组件模板、数据契约、字段映射契约、模板状态 |
| `dashboard` | 大屏元数据、草稿配置、卡片实例配置 |
| `dashboard-preview` | 草稿预览、卡片查询、发布前体检 |
| `dashboard-publish` | 发布版本快照、当前发布版本切换、回滚预留 |
| `runtime` | 浏览页加载、单卡片运行、错误隔离、缓存预留 |
| `diagnostic` | 查询日志、错误诊断、脱敏诊断信息 |
| `security-reservation` | 用户上下文、权限校验接口、License 校验接口预留 |
| `manifest` | Dashboard Context Manifest 结构生成预留 |

## 5. PostgreSQL 数据库表设计

第一阶段只建设平台配置库，不绑定外部水务业务表。

| 表名 | 用途 | 核心字段 |
| --- | --- | --- |
| `data_source` | 数据源基础信息 | `id`、`code`、`name`、`type`、`environment`、`status`、`config_json`、`secret_ref` |
| `data_source_health_log` | 连接测试与健康记录 | `id`、`data_source_id`、`result`、`latency_ms`、`error_code`、`trace_id` |
| `component_template` | 组件模板 | `id`、`template_code`、`name`、`category`、`render_engine`、`version`、`status` |
| `component_template_version` | 模板版本与契约 | `id`、`template_id`、`version`、`data_contract_json`、`default_config_json`、`checksum` |
| `dashboard` | 大屏基础信息 | `id`、`dashboard_code`、`name`、`status`、`current_published_version_id` |
| `dashboard_draft` | 当前草稿 | `id`、`dashboard_id`、`revision`、`config_json`、`updated_by`、`updated_at` |
| `dashboard_card` | 草稿卡片实例索引 | `id`、`dashboard_id`、`card_code`、`template_code`、`enabled`、`ai_enabled`、`config_json` |
| `dashboard_version` | 不可变发布版本 | `id`、`dashboard_id`、`version_no`、`snapshot_json`、`checksum`、`published_by`、`published_at` |
| `dashboard_publish_log` | 发布与回滚审计 | `id`、`dashboard_id`、`version_id`、`action`、`result`、`trace_id` |
| `card_query_log` | 卡片 SQL 执行日志 | `id`、`dashboard_id`、`card_id`、`data_source_id`、`sql_hash`、`duration_ms`、`result`、`trace_id` |
| `runtime_error_log` | 运行错误日志 | `id`、`resource_type`、`resource_id`、`error_code`、`error_summary`、`diagnostic_json`、`trace_id` |
| `audit_log` | 配置变更审计 | `id`、`operator_id`、`action`、`resource_type`、`resource_id`、`change_summary`、`trace_id` |

设计要求：

- 主键建议使用 UUID，配置 JSON 使用 `jsonb`。
- 所有表包含创建时间、更新时间和必要的操作人字段。
- `dashboard_version.snapshot_json` 发布后不可修改。
- 草稿、发布版本和组件配置 JSON 必须具备版本号或结构版本字段。
- 密码、Token、连接串不得存入可返回前端的 `config_json`。
- `secret_ref` 指向服务端加密密钥存储，不返回密钥内容。

## 6. 数据源配置中心接口设计

所有接口统一返回 `success`、`code`、`message`、`data`、`traceId`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/data-sources` | 查询数据源列表 |
| `POST` | `/api/data-sources` | 新增数据源 |
| `GET` | `/api/data-sources/{id}` | 查询数据源详情，不返回密钥 |
| `PUT` | `/api/data-sources/{id}` | 修改数据源 |
| `POST` | `/api/data-sources/{id}/test` | 测试连接 |
| `POST` | `/api/data-sources/{id}/enable` | 启用数据源 |
| `POST` | `/api/data-sources/{id}/disable` | 停用数据源 |
| `POST` | `/api/data-sources/{id}/sql-preview` | 执行安全 SQL 预览 |

`sql-preview` 必须执行 SQL 解析、只读账号校验、仅允许 `SELECT`、参数化、限行、超时、审计和脱敏。

## 7. 组件模板接口设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/component-templates` | 查询可用模板 |
| `POST` | `/api/component-templates` | 新增模板 |
| `GET` | `/api/component-templates/{id}` | 查询模板详情 |
| `PUT` | `/api/component-templates/{id}` | 修改模板基础信息 |
| `POST` | `/api/component-templates/{id}/versions` | 创建模板版本 |
| `POST` | `/api/component-templates/{id}/enable` | 启用模板 |
| `POST` | `/api/component-templates/{id}/disable` | 停用模板 |

模板至少包含 `templateCode`、`version`、`renderEngine`、`dataContract`、`defaultConfig`、`fieldMappingSchema`、`minWidth`、`minHeight`，并预留 `licenseScope`、`signature`、`checksum`。

## 8. 大屏编辑器接口设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/dashboards` | 查询大屏列表 |
| `POST` | `/api/dashboards` | 新建大屏 |
| `GET` | `/api/dashboards/{id}` | 查询大屏基础信息 |
| `GET` | `/api/dashboards/{id}/draft` | 加载草稿 |
| `PUT` | `/api/dashboards/{id}/draft` | 保存完整草稿配置 |
| `POST` | `/api/dashboards/{id}/draft/cards` | 新增卡片实例 |
| `PUT` | `/api/dashboards/{id}/draft/cards/{cardId}` | 修改卡片配置 |
| `DELETE` | `/api/dashboards/{id}/draft/cards/{cardId}` | 删除草稿卡片 |
| `POST` | `/api/dashboards/{id}/draft/cards/{cardId}/preview` | 预览单卡片 |
| `POST` | `/api/dashboards/{id}/draft/inspect` | 执行发布前体检 |

草稿配置必须完整序列化画布、卡片、布局、数据绑定、字段映射、样式、刷新和 AI 预留配置。

## 9. 发布版本接口设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/dashboards/{id}/publish` | 体检通过后发布版本 |
| `GET` | `/api/dashboards/{id}/versions` | 查询历史版本 |
| `GET` | `/api/dashboards/{id}/versions/{versionId}` | 查询版本快照 |
| `POST` | `/api/dashboards/{id}/versions/{versionId}/rollback` | 回滚预留 |
| `GET` | `/api/dashboards/{id}/publish-status` | 查询当前发布状态 |

发布前必须再次执行体检。发布版本是不可变快照，草稿保存不得修改当前发布版本。回滚应将历史快照发布为新版本，不直接修改旧版本。

## 10. 浏览页加载接口设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/runtime/dashboards/{dashboardCode}` | 加载当前已发布大屏 |
| `POST` | `/api/runtime/dashboards/{dashboardCode}/cards/{cardCode}/query` | 查询单卡片数据 |
| `GET` | `/api/runtime/errors/{traceId}` | 管理员查询脱敏诊断 |

浏览页只加载已发布快照，不返回草稿、数据源密钥、原始连接串或敏感诊断信息。每张卡片独立请求、独立加载、独立错误边界，状态至少覆盖 `loading`、`success`、`empty`、`error`、`forbidden`。

## 11. Dashboard Context Manifest 预留设计

第一阶段不调用 AI，仅在发布快照中预留以下结构：

```json
{
  "dashboardId": "uuid",
  "versionId": "uuid",
  "generatedAt": "2026-06-04T00:00:00Z",
  "cards": [
    {
      "cardId": "uuid",
      "cardCode": "supply-trend",
      "enabled": true,
      "aiEnabled": false,
      "semantic": "",
      "allowedFields": [],
      "dataContract": {},
      "permissionScope": {}
    }
  ]
}
```

Manifest 只能基于已发布版本生成，只包含已拖入、已启用、允许 AI 的卡片。后续必须经过用户权限、字段权限和脱敏规则过滤，且不得包含数据库密码、Token、连接串和未授权原始数据。

## 12. 错误诊断与 traceId 设计

- 每个 HTTP 请求进入系统时生成或接收 `traceId`。
- `traceId` 写入统一响应、应用日志、SQL 查询日志、发布日志和错误日志。
- 卡片查询额外记录 `dashboardId`、`cardId`、`dataSourceId`、`sqlHash`、耗时和错误码。
- 普通用户只看到友好提示和可用于报障的 `traceId`。
- 管理员诊断只展示脱敏 SQL 摘要、错误码、耗时和处理建议。
- 密码、Token、连接串、密钥、完整堆栈不得返回前端。
- 单卡片异常由卡片错误边界处理，不能导致整屏崩溃。

## 13. 权限与 License 预留点

- 所有服务方法接收 `UserContext`。
- 所有资源具备 `createdBy`、`updatedBy`、`ownerId` 或权限扩展字段。
- 数据源、模板、大屏、发布、浏览、诊断接口设置权限校验入口。
- `component_template` 预留 `license_scope`、`signature`、`checksum`。
- 系统启动和发布接口预留 License 状态检查。
- Dashboard Context Manifest 预留用户权限和字段权限过滤入口。
- 管理员诊断接口与普通浏览接口严格分离。

## 15. 开发顺序

1. 最终确认前后端基础框架与工程目录。
2. 建立独立启动骨架、统一响应、异常处理和 `traceId`。
3. 建立 PostgreSQL 平台配置库迁移机制。
4. 开发数据源配置中心和安全连接测试。
5. 开发 SQL 安全解析、预览、限行、超时和审计。
6. 开发组件模板管理与基础 ECharts 图表模板。
7. 开发大屏元数据、草稿和卡片实例配置。
8. 开发大屏编辑页、拖拽画布和卡片数据配置。
9. 开发发布前体检和不可变版本发布。
10. 开发浏览页加载与单卡片错误隔离。
11. 开发管理员脱敏诊断抽屉。
12. 预留 Dashboard Context Manifest、权限和 License 扩展点。
13. 完成集成测试、端到端测试和开发记忆体更新。

## 16. 验收标准

- 系统可独立部署、独立启动、独立访问。
- PostgreSQL 平台配置库可正常初始化。
- 管理员可新增只读数据源并执行连接测试。
- 前端无法获取数据库密码、Token、连接串或密钥。
- 非 `SELECT` SQL、多语句 SQL 和危险 SQL 被拒绝。
- SQL 预览具备限行、超时、审计和 `traceId`。
- 管理员可维护至少一种基础 ECharts 组件模板。
- 用户可创建大屏、拖入卡片、选择数据源、配置 SQL 和字段映射。
- 草稿保存后不影响已发布浏览页。
- 发布前体检能识别数据源、SQL 和字段映射问题。
- 发布后生成不可变版本快照，浏览页只加载已发布版本。
- 任意单卡片查询失败时，其他卡片继续正常展示。
- 普通用户只看到友好错误提示和 `traceId`。
- 管理员可查看脱敏诊断信息。
- 发布快照中已预留 Dashboard Context Manifest 结构。
- 权限与 License 校验入口已预留，但未被绕过。
- 所有接口返回 `success`、`code`、`message`、`data`、`traceId`。

## 基础框架选型建议

推荐方案，待进入第一阶段第 1 步编码前最终确认：

- 后端：Java Spring Boot
- 前端：Vue 3 + Vite + TypeScript + Pinia + Vue Router
- 数据库：PostgreSQL + PostGIS

选择理由：

- Spring Boot 适合长期维护的独立微服务产品，具备成熟的配置、健康检查、日志、异常处理、数据库迁移、安全与可观测能力生态。
- Java 类型系统和成熟工程规范更适合承载数据源安全、SQL 审计、发布版本、权限与 License 等高约束服务端能力。
- Vue 3 技术栈与 V17 文档中已有 Vue 组件语境一致，适合大屏编辑器和配置型管理页面，也便于后续集成 ECharts、OpenLayers、Babylon.js 和 G6。
- PostgreSQL + PostGIS 是 V17 已固定的平台数据库与空间数据库技术路线。
- NestJS 结构清晰且开发效率较高，但本产品后续将包含多数据源、安全审计、授权、诊断和长期政企部署要求，Spring Boot 的长期维护确定性更高。
